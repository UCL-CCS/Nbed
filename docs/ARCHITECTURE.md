# Nbed architecture

Nbed implements projection-based embedding: a cheap mean-field (DFT) calculation on
the whole molecule is partitioned into an *active* fragment and an *environment*, and
the fragment is re-solved at a higher level of theory (HF, or a correlated
wavefunction / quantum Hamiltonian) inside an embedding potential generated by the
environment.

Since v0.1.0 the package is a small set of functions and one class rather than a
config-driven driver. The user owns the PySCF objects throughout; Nbed only builds the
partition, the embedded SCF, and the integrals.

## Modules

| Module | Role |
|---|---|
| `backend.py` | Array / chemistry backend switch. Module globals `xp` (numpy or cupy), `pyscf` (pyscf or gpu4pyscf) and `USING_GPU`, set by `set_backend(use_gpu)`. Other modules read them as `backend.xp`, so the switch takes effect at call time. |
| `act_env_space.py` | Chooses which MOs of the global mean field belong to the fragment. |
| `emb_scf.py` | `EmbedSCF`: builds the partitioned densities, the embedding potential, and the embedded DFT/HF calculation with a mu or Huzinaga projector. Also exports CASCI integrals. |
| `emb_scf_gpu.py` | `EmbedSCF_GPU`: a copy of `emb_scf.py` hard-wired to cupy / gpu4pyscf. |
| `cas_space.py` | Chooses a correlated active space *inside* the embedded fragment and diagnoses how strongly correlated it is. |
| `hamiltonian.py` | Turns spatial MO integrals into spin-orbital integrals and OpenFermion operators. |
| `grad.py` | Prototype analytic nuclear gradient of the mu-projected HF-in-DFT / DFT-in-DFT energy. |

## Pipeline

```
global KS  (dft.RKS / dft.ROKS on the whole molecule)
   │   optional: localise orbitals within occ/virt blocks (e.g. Pipek-Mezey; done by the user)
   ▼
act_env_space.select_act_env_space(mf, atom_indices, n_occ_active, n_vir_active, mo_coeff, max_spread)
   │   rank occupied and virtual MOs separately by Lowdin population on the target atoms,
   │   optionally rejecting diffuse orbitals by orbital_spread
   ▼   → active_idxs, env_idxs
EmbedSCF(global_scf, active_idxs, env_idxs, C, mo_occ, S, max_memory, mu_val)
   │   reorder columns to [occ_env | occ_act | vir_act | vir_env]  (PySCF CAS order)
   │   dm_full = dm_act + dm_env ;  E_DFT = E_act + E_env + E_cross
   │   G_emb = G[dm_full] - G[dm_act]      (Roothaan effective Fock for ROKS)
   │   mol_act: same atoms and basis, charge/spin chosen so it holds only the active electrons
   ▼
build_emb_dft(xc, proj_type="mu"|"huz", ...)   or   build_emb_hf(proj_type=..., ...)
   │   mu  : hcore += mu * S C_env C_env^T S + G_emb           (density independent)
   │   huz : hcore += G_emb ; get_fock adds -(F P + P^T F), P = D_env S, rebuilt every cycle
   │   start from dm_act; run the SCF
   ▼   → E_emb = E_sub + E_env + E_cross - tr(dm_act v_emb),  mf_emb, emb_corr, env_cols, ...
        │
        ├─ get_mo_integrals(mf_emb, C, norb, nelecas, mo_cas_idxs)  → (E_core, h1, eri)
        │        uses the embedded hcore *without* the Huzinaga term (always on CPU)
        │
        └─ cas_space.select_cas_by_mp2_no(mf_emb, atom_indices, n_cas_vir, env_cols=...)
                 stage 1  fragment_valence_projector → valence_virtual_rotation
                          → pool of fragment-valence virtuals → semicanonicalize
                 stage 2  pool_mp2_natural_orbitals (MP2 with frozen = everything else)
                 → CASSelection(c_full, mo_cas_idxs, nelecas, natural occupations, ...)
             run_casci / run_casscf (the latter checks environment_overlap)
             diagnose_cas → unpaired electrons, orbital entropies, reference weight
   ▼
hamiltonian.build_spin_integrals(h1, eri, norb) → build_molecular_H(E_core, h1_spin, eri_spin,
                                                                   "jordan_wigner" | "fermion" | other)
```

## The embedding energy

With `v_emb = hcore_mod - hcore`, the energy reported by `build_emb_*` is

```
E_emb = E_sub[gamma_A^emb; hcore + v_emb] + E_env + E_cross - tr(gamma_A v_emb)
```

where `gamma_A` is the *original* active density. For DFT-in-DFT with the Huzinaga
projector this reproduces the global DFT energy exactly. With mu it is exact only as
mu → ∞, with an error of order 1/mu.

## Design invariants

- **Orbitals are chosen by role, never by column position.** After Huzinaga embedding,
  the environment orbitals are shifted only by |eps_env| and end up scattered among the
  virtuals. `env_cols` is recomputed from each orbital's weight on the occupied
  environment, and every CAS helper excludes it explicitly.
- **mu lives in `hcore` and Huzinaga lives in `get_fock`.** PySCF evaluates `get_hcore`
  once, so the density-dependent Huzinaga operator has to be rebuilt in `get_fock`. As a
  result, anything that builds its own Hamiltonian from `get_hcore` (CASSCF) does not
  see the projector, which is why `run_casscf` needs a frozen projector passed in
  `hcore`.
- **Selection is a rotation inside a span.** CAS selection only rotates within
  environment-free columns, so it is orthogonal to the environment to round-off.
  Orbital optimisation carries no such guarantee.
- **Restricted references only.** UHF/UKS inputs are rejected, and open shells go
  through ROKS/ROHF.

## Known issues and numerical caveats

- `emb_scf_gpu.py` duplicates `emb_scf.py`, even though `backend` already abstracts
  the difference.
- `check_embedding` asserts an environment overlap below 1e-8, which a mu projector
  (leaking at O(1/mu)) does not meet. Use it with Huzinaga.
- Huzinaga HF-in-DFT can oscillate without converging (formamide/STO-3G, O fragment).
  `warn_not_converged` reports it, and `huz_level_shift=1.0` fixes it.
- E_xc of the partial active density is orientation-dependent on the DFT grid: rotating
  water changes the B3LYP HF-in-DFT energy by ~2-4e-4 Ha at the default grid level.
  DFT-in-DFT cancels this error; HF/WF-in-DFT does not. Use `grids.level >= 5`
  (unpruned) when comparing geometries.

## Tests

`tests/` contains property-based tests (`hypothesis`) for every module, plus numeric
snapshots in `tests/snapshots/` for H2, H2O, CH3OH, formamide, acetonitrile and CH3•.
Run `uv run pytest`. After an intended change in results, run
`uv run pytest tests/test_snapshots.py --snapshot-update` and review the diff.

## Nuclear gradients (`grad.py`, prototype)

`embedding_gradient(emb, mf_emb)` differentiates the energy returned by
`build_emb_hf` / `build_emb_dft` (mu projector, closed shell, canonical partition). It
follows the Lagrangian of Lee et al., *J. Chem. Phys.* **151**, 074104 (2019):

- the embedded SCF is variational, so it contributes only an energy-weighted density;
- a Z-vector (CPKS, `pyscf.scf.cphf`) handles the global KS orbital response;
- closed-form multipliers enforce the canonical condition `F_ab = 0` that fixes which
  occupied orbitals belong to the fragment (a ≠ b degenerate pair raises an error).

The fragment density gamma_A is not a physical density, and its xc energy has a large
DFT grid-weight response, up to 2e-2 Ha/bohr for B3LYP. That response has to be
included, because the grid moves with the atoms. PySCF's Hessian `make_h1` has no grid
response, so fixed-density Fock derivatives are instead taken as a central difference
*in density space* of the grid-response energy gradient (`fock_deriv_contract`). That
difference is exact for h/J/K and O(eps²) for xc. It agrees with geometric finite
differences to ~1e-8 Ha/bohr for HF, LDA, PBE and B3LYP on water and methanol.

Next steps: Huzinaga (response of the projector to the embedded Fock), Pipek-Mezey
partitions (localisation Hessian), ROKS, WF-in-DFT via relaxed densities from
PySCF's MP2/CCSD/CASCI gradients, a fully analytic xc grid response, and the GPU
path via `gpu4pyscf.grad`.
